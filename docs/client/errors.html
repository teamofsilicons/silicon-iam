Six error variants, chosen so that the right recovery is decidable from the type alone. Nothing in this crate returns a stringly-typed failure you have to parse.

The taxonomy

VariantMeansRecovery
Configuration Local input is invalid — a malformed origin, a bad credential, a non-HTTPS base URL. Fix the deployment. Never retryable.
Handshake The compatibility handshake failed closed. No client exists. Upgrade the SDK or the backend. Never retryable.
Transport The HTTP exchange failed with no usable API response. Retryable only with the same idempotency key.
Api Silicon IAM returned a documented error. Carries status, code, request ID and retry metadata. Ask is_retryable().
Protocol A successful-looking response violated the negotiated contract. Never retryable. This is a bug, in the SDK or the backend — report it.
Crypto A local cryptographic operation failed. Never retryable.
AmbiguousOboVerification A single-use proof may already have been consumed. Never retry. Fail the request.

Reading an API error

match client.oauth().refresh(token).send().await {
    Ok(replacement) => { /* … */ }
    Err(Error::Api(api)) => {
        let _status = api.status();
        let _code = api.code();
        let _request_id = api.request_id();

        if let Some(wait) = api.retry_after() {
            // Honour this exactly. Do not shorten it.
        }
        if let Some(limit) = api.rate_limit() {
            let _remaining = limit.remaining();
            let _resets_in = limit.reset_after();
        }
    }
    Err(other) => return Err(other),
}

Branch on code(), never on message() — the message is prose for a human and may be reworded without a contract change. Log request_id(); it is the fastest way to get a specific failure investigated. The full code list is in the contract's error index.

Errors never carry credentials. Every variant is secret-free by construction, so the whole error is safe to log verbatim.

Transport failures

TransportErrorKind distinguishes Connection, Timeout, Request and Response. The distinction matters because it tells you whether the server could have seen the request at all:

  • Connection — it did not. Safe to rebuild and resend.
  • Timeout, Response — it may have. The mutation may already have applied. Resend with the same idempotency key, never a new one.

The recovery rule, in one sentence

Retain the operation after an uncertain outcome; never recover by issuing a new key for the same mutation. A fresh key turns a replay into a second execution. On a refresh, that revokes the user's entire 900-day family.

Concretely, for every mutating call:

  1. Build the operation and read idempotency_key().
  2. Persist the key with its input before sending.
  3. On success, retire the key in the same transaction that commits the result.
  4. On Transport or Protocol, keep both and rebuild the identical operation later with the *_with_idempotency_key constructor.
  5. On an authoritative terminal Api error, retire the key. The mutation will never succeed.

What the SDK retries for you

Safe and idempotent calls retry inside a small bounded policy — a few attempts, jittered. You do not need to wrap them.

Two deliberate exceptions. A server Retry-After longer than that internal policy is surfaced to you rather than silently waited out, because a thirty-second stall inside a library call is worse than an error you can schedule around. And OBO verification is never retried at all, for the reason in Delegated access.

What to log

AlwaysNever
request_id(), status(), code(), the operation name, and your own idempotency key Token or proof values, the Application secret, a webhook secret, or a raw callback query string

The first column is everything needed to trace a failure end to end. The second is redacted from Debug throughout the crate, so logging a whole error or a whole client is safe — but a value you deliberately unwrapped with expose_secret is yours to keep out of the log.
