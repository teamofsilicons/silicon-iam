An application is a registered confidential OAuth client. It is owned by an organization and administered by that organization's owner and administrators — but anyone may sign in through it.

Registration

POST /api/v1/applications takes the application ID, the owning organization, at least one redirect URI, a webhook URL, and the scopes it wants.

The response carries two credentials you will never see again. The client secret (256 bits) and the whs_… webhook signing secret. Both are kept only as keyed digests. The response is replayable for ten minutes with the same idempotency key, and then unrecoverable.

A new application lands in under_review and cannot complete an authorization until Silicon approves it. Later changes that widen authority — a new redirect URI, a new scope, a new webhook destination — are held as has_pending_changes and reviewed the same way, so an approved application cannot quietly grow.

StatusMeaning
under_reviewRegistered; cannot authenticate anyone yet

deletedTerminal. The ID is never reused.

Signing a user in

Authorization code with PKCE. Five steps, three of them yours.

  1. Navigate the user agent to GET /api/v1/oauth/authorize with response_type=code, client_id, redirect_uri, scope, state (16–512 characters), code_challenge and code_challenge_method=S256. Optionally org_id.
  2. IAM answers with the consent screen, or redirects straight back when consent already covers the requested scopes.
  3. The user agent arrives at your exact registered redirect_uri with code and the unchanged state.
  4. Your server exchanges the code at POST /api/v1/oauth/token, authenticating with HTTP Basic. The code lives two minutes and is single use.
  5. Use the access token. It lives 30 minutes; the refresh token rotates on every use.

The redirect URI must match a registered, currently active URI exactly. A protocol error returns to that URI using OAuth query fields with state unchanged; errors raised before a redirect URI is trusted use the JSON envelope instead.

Introspection

Tokens are opaque and there is nothing to verify locally. When an application needs to know whether a token is good right now — after a revocation, or a membership change — it calls POST /api/v1/oauth/introspect with its Basic credentials. The response reflects current revocation and membership state.

Webhooks are a notification channel, not an authorization one. Never substitute a delivered event for an online check.

Consent

Whether a user is prompted is a backend-only policy (notify_users). It is set by Silicon during review, is never returned by the organization-facing endpoints, and organization administrators cannot see or change it.

Credentials

POST /api/v1/applications/{app_id}/client-secret-rotations issues a replacement and reveals it once. It requires a verified-channel step-up token bound to application.client_secret.rotate and an If-Match.

The previous secret stops working immediately. Deploy the replacement to every instance before rotating, not after.

Redirect URIs are a history, not a set

Adding a URI retires the previously active one, and retired entries stay visible with their approval and retirement timestamps. An application that has silently forgotten which URI it used last month is an application nobody can debug.

EndpointNotes
GET /api/v1/applications/{app_id}/redirect-urisFull history
POST /api/v1/applications/{app_id}/redirect-uris Adds one; retires the previous active URI
DELETE /api/v1/applications/{app_id}/redirect-uris/{id} Retires one. Returns 200 with the mutation, not 204.

Webhook destination

PUT /api/v1/applications/{app_id}/webhook proposes a replacement and answers 202: deliveries continue to the current URL until Silicon approves the new one. The existing encrypted signing secret is reused, so no new secret is returned.

Delivery, signature verification and dead-letter replay are covered under Webhooks.

Login history

GET /api/v1/applications/{app_id}/login-history records every authentication attempt through this application, successful or not, retained for one year. Each entry carries the actor, the event type, the outcome and a request_id.
